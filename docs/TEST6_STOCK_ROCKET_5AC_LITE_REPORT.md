## Key Findings

### 1. ⚡ The WMAC is already active on stock firmware as `airview1`

```
airview1  IEEE 802.11na  ESSID:"spectral"
          Mode:Monitor  Frequency:4.92 GHz  Access Point: Not-Associated
          Bit Rate:130 Mb/s   Tx-Power=13 dBm
          Noise level=-105 dBm
```

**The stock Ubiquiti AirOS firmware already initializes and uses the QCA955x on-chip WMAC** for its AirView spectral scanning feature. The interface is:

- Named `airview1`
- In **Monitor mode**
- Tuned to **4.92 GHz** (below standard 5 GHz band — likely a safe parking frequency)
- ESSID set to `"spectral"` — clearly the AirView spectral engine
- Tx power at 13 dBm
- Noise floor: **-105 dBm**

### 2. ⚠️ WMAC caldata uses default template (no valid factory cal)

From `dmesg`:
```
ar9300_eeprom_restore_internal[4673] No vaid CAL, calling default template
```

This confirms:
- The XC board (Rocket 5AC Lite) has **no valid factory WMAC calibration data** at the expected EEPROM location
- The AR9300 driver falls back to a **built-in default template**
- Ubiquiti's AirView runs the WMAC spectral scanner using this default template — they apparently consider it adequate for spectral-only use

### 3. Production radio (`ath0`) is fully operational

```
ath0      IEEE 802.11ac  ESSID:"Lightsabersforyou"
          Mode:Master  Frequency:5.745 GHz
          Bit Rate:173.3 Mb/s   Tx-Power=25 dBm
```

The ath10k-equivalent production radio runs normally alongside the WMAC.

### 4. Proprietary driver stack — no standard Linux wireless tools

AirOS uses:
- Proprietary QCA `ol_` driver framework (not upstream `ath9k`/`ath10k`)
- `iwconfig` instead of `iw`
- No nl80211, no debugfs spectral interface
- Firmware download messages: `ol_transfer_bin_file` for PTP/PTMP modes
